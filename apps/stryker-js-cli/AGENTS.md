# AGENTS.md — `@systemfsoftware/stryker-js-cli`

The `stryker` bin: NDJSON run-event framing, mode/colour detection, signal handling, drain-before-exit, classed exit code. Parent: root `AGENTS.md`.

## Rules

| ID         | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Gate                                                                                                                                                                                                                                |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **CLI-B1** | Never drop the `prepare` script (`tsdown`) and never point `bin` at a committed shim: the bin target is gitignored `dist/main.mjs`, and pnpm links `.bin` shims before and after lifecycle scripts — without `prepare` the shim targets nothing and `stryker run` dies with `stryker: not found` on a fresh install.                                                                                                                                                  | Fresh `pnpm install` followed by `pnpm --filter @systemfsoftware/stryker-js-cli exec stryker --help` exits 0                                                                                                                        |
| **CLI-M1** | This package carries no mutation lane: `stryker.config.json` and the `mutation`/`mutation:full` scripts are not carried in this repository, so nothing here enrolls a mutated set. Do not re-add one without a gate that reads it.                                                                                                                                                                                                                                    | `review` — no manifest script names `mutation` or `mutation:full`                                                                                                                                                                   |
| **CLI-S1** | `package.json#exports` is tsdown-generated (REPO-S4) and carries only `./package.json`: this package is a bin and publishes no program entry, but a tool that reads a package's manifest by specifier still finds it (`exports.packageJson`, on by default — the tshy convention). Author it in `tsdown.config.ts` as `exports: { packageJson: true, exclude: [<every entry>], bin: { stryker: './src/main.ts' } }`; never hand-edit the manifest.                    | `node -p "JSON.stringify(require('./packages/stryker-js-cli/package.json').exports)"` prints `{"./package.json":"./package.json"}`                                                                                                  |
| **CLI-D1** | The bundle imports nothing but `node:` builtins, which is what licenses the manifest's empty `dependencies`: each of them is a build input, never a runtime need. A dependency that cannot be inlined is a build error, not a new runtime dependency.                                                                                                                                                                                                                 | `pnpm --filter @systemfsoftware/stryker-js-cli build` fails on any emitted import that is not `node:` (`deps.onlyImport: [/^node:/]` in `tsdown.config.ts`)                                                                         |
| **CLI-D2** | The parser is the WASI build, aliased from `oxc-parser`; a platform-native binding cannot be inlined once for every platform. The alias asserts parser and binding versions are equal, and the `.wasm` ships beside the chunks (`files` is `dist`). The instrumenter parses through the binding's synchronous entry, so the async pool's `wasi-worker.mjs` is neither emitted nor needed.                                                                             | `pnpm --filter @systemfsoftware/stryker-js-cli build` throws on a version mismatch; `test -f packages/stryker-js-cli/dist/parser.wasm32-wasi.wasm` passes after it; `node dist/main.mjs --version` writes nothing to standard error |
| **CLI-D3** | The engine loads the HTML reporter as a plugin module, so it ships as its own entry referenced by a relative URL, and its client bundle is baked at build time by `define` — a bundled reporter cannot resolve that asset from disk.                                                                                                                                                                                                                                  | `pnpm --filter @systemfsoftware/stryker-js-cli exec node -e "const s=require('fs').readFileSync('dist/reporters/html.mjs','utf8'); if(!s.includes('MutationTestElements')) process.exit(1)"` exits 0                                |
| **CLI-D4** | The packed-install closure is now gated by `apps/stryker-js-cli-e2e`'s packed-install journey (`pnpm test:e2e`): it installs the packed tarball with `npm install -g` in a pinned container and asserts the installed bin runs. This repository still carries no `test:contract` script — the lane's task is `test:e2e`, a different name by design.                                                                                                                  | `review` — no manifest script names `test:contract`                                                                                                                                                                                 |
| **CLI-L1** | `oxlint.config.ts` extends the aggregate `all` preset from `@systemfsoftware/all` and, in this repository, adds exactly the workspace strict trio (`typescript/no-unnecessary-condition`, `typescript/strict-boolean-expressions`, `typescript/no-non-null-assertion`) plus the no-ternary / consistent-type-assertions / no-restricted-imports deltas the migration plan (KTD2) authorizes; `@systemfsoftware/oxlint-config` is not a dependency of this repository. | `pnpm --filter @systemfsoftware/stryker-js-cli lint` exit...                                                                                                                                                                        |
