# Agent-Facing Surfaces: Audit

What a coding agent can read from each surface on `main`, and the gaps between that and the plan `docs/plans/2026-10-10-0141-feat-agent-surfaces-plan.md`. Every `path:line` cite is at `main` `cfdf3cdc3`. The corpus figures come from an older artifact (see Sources) and are not re-measured at `cfdf3cdc3`.

Budget: 10,000 bytes for an agent's default output (R11). Codex truncates tool output at 10,000 bytes by default. Claude Code warns at 10,000 tokens.

## Sources of the figures

- **Corpus.** Artifact `mutation-report-416`, run 37960922409, built from `main` `1e1de6d05`. The `mutation.json` file is 3,370,201 B. It holds 8,626 mutants in 156 files: 1,035 Survived, 451 NoCoverage, 20 Timeout, 1,797 Killed, 4,136 CompileError and 1,187 Ignored. That gives 1,506 actionable mutants (Survived, NoCoverage, Timeout, RuntimeError). The report predates #262, so the corpus has no mutant with `statusReason`, `coveredBy`, `killedBy` or `description`, and all 156 file sources are empty.
- **Stream and MCP sizes.** These are the corpus encoded through `main`'s wire shapes, as compact JSON. Stream lines use `cost: null`. The surfaced set uses 1 survivor per line and 7 per file. They are models, not captured output.
- **Logs.** `gh run view --log-failed` was re-run on 2026-10-10:
  - ci #925 (run 37953877772, head `b4c583923`): 1,472 lines, 157,260 B.
  - mutation #413 (run 37942966476, head `27f493b63`): 523 lines, 59,162 B.
  - Both print `UNKNOWN STEP` as the step name on every line.
- **Annotations.** Read through `check-runs/<job>/annotations` on the failed jobs of run 37953877772.

## Changes since the plan's baseline (`1e1de6d05` -> `cfdf3cdc3`)

- **#262.** Stream `7.0`. `Ignored` lines carry `<rule-id>: <detail>`. Other statuses carry `statusReason: string | null`. The merged report keeps `statusReason`. Remembered results reuse the prior entry's `statusReason` instead of the bare `Remembered` placeholder (`run/incremental-reuse.cell.ts:477-489`). This is the stream major the plan meant to take in U3 (R30). It is still unreleased, so U3 shares it.
- **#258 rename.** `checker` is in `RULE_IDS` (`ignore-rule.schema.ts:19`), so the vocabulary has 13 codes. U2 does not add it again.
- **#263.** Kill-matrix lane, with the repo's first step summary and actionable `::error` titles. U9 and U12 reuse its style.
- **README.** The stream sample is current (`7.0`). R28 still applies, because nothing checks it.

## SARIF decision (KD13)

- **Cost.** Rule `fullDescription` and `help` would add one string per rule: 13 rules on the corpus, against a 376,746 B log. A truncation note would add one `run.properties` or notification entry. Both are negligible.
- **Readers.** No reader consumes either. No workflow uploads SARIF, because code-scanning upload is out of scope (KD13). The only in-repo reader is `packages/stryker-js/tests/sarif-reporter.integration.test.ts:283`, which reads `runs` and results.
- **Decision.** U8's SARIF half (rule help, `fullDescription`, the truncation note) moves to Scope Boundaries as "considered and not built". U8 keeps annotate levels, `--limit` and failure annotations.

## Facts the agent cannot reach without prose today

1. Why a non-Ignored mutant has its status.
2. What kills a survivor.
3. Which tests cover a survivor in a CI-produced report.
4. Whether a merge failed or a score fell.
5. Which annotations GitHub dropped.
6. What the reason codes mean, unless the agent reads schema annotations in source.
