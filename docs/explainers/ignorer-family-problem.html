Subject
The three nested problems behind packages/ignorers/* in stryker-js-effect — and which one your RuleTester complaint actually targets

“The problem” is three problems stacked on top of each other, and most of the frustration of the last three rounds comes from each discussion solving a different layer than the one being asked about.

  1. The domain problem — some mutants cannot be killed, so the mutation score lies.
  2. The contract problem — where the “ignore this” decision lives, who walks the AST, and what a third-party ignorer is allowed to be.
  3. The authoring problem — how a human writes and tests one. This is the layer you keep hitting, and it is the one that has never been built.

1Mutants that cannot die

StrykerJS works by mutating your code and running your tests: every mutant a test suite fails to kill is a gap in the suite. That logic assumes every mutant can be observed. Two shapes of code in this repo break that assumption:

  • Proven-equivalent mutants in Effect Schema declarations. A schema's identity markers are nominal data, not behavior. Mutate the tag string and validation still works; mutate it the other way and no test can tell. Concretely: Schema.Tag("id", "Error", number), brand names in Schema.brand(...), the tag/fields pair in Schema.TaggedClass(...), S.optionalWith defaults, and documentation annotations. Mutating these produces equivalent mutants — the score drops, and no amount of testing recovers it.
  • Unreachable mutants in in-source test blocks. if (import.meta.vitest) { ... } is test code that never runs in production. Mutants inside it are noise: they say nothing about your production behavior, they just drag the percentage down.

Both are classes of nodes where the mutant should never be counted in the first place. That is the whole reason the ignorer family exists: a named, reason-carrying exclusion so the report says “excluded, and here is why” instead of silently failing to reach 100%.

2Where the decision lives — the contract that was solved

A mutation engine walks the parsed AST, proposes mutants at candidate nodes, and at that moment needs to ask: “does any ignorer exclude this node?” Several sub-problems had real answers shipped (the walker-contract plan, PR #17):

  • Third-party loading. Ignorers load like ESLint plugins — the engine scans installed @systemfsoftware/stryker-ignorer-* modules for a strykerIgnorers export, validates it structurally (name is a string, shouldIgnore is callable), and registers each entry as an Ignore contribution. A bad module is rejected at load, by name.
  • Who walks. The host (instrumenter) supplies the single oxc-walker and consults every ignorer at each node with (node, ancestors), ancestors nearest-first. No ignorer package rolls its own traversal — that duplication is what the refactor deleted.
  • What an ignorer is. A pure, zero-Effect, per-node decider. The entire published contract is:
// packages/ignorers/interface/src/mod.ts — the whole runtime story
export interface Ignorer {
  readonly name: string
  shouldIgnore(node: Node, ancestors: readonly Node[]): string | undefined
}

The trade this contract made: everything an ignorer receives is typed as the full oxc node union (~372 node kinds) plus an ancestors array. That keeps the seam tiny, host-owned, and Effect-free — but it hands each ignorer the narrowing problem, which is where the pain you keep describing actually lives. The effect-schema package answers that union with 33 hand-written unknown-guards (isAstNode, hasCalleeNode, hasMemberEnds, …) before any domain logic runs.

3The layer that was never built — authoring and testing

oxlint and ESLint separate three layers, and that separation is exactly why their rules feel good to write and test. This repo built one of the three:

oxlint / ESLint rulesstryker ignorers today
Wire contract
what the host calls		 the compiled rule object the linter core dispatches ✓ Ignorer { name, shouldIgnore(node, ancestors) } — engine-validated, host-walked
Authoring API
what a human writes		 create(context) returning visitors keyed by node type — the runtime dispatches, each visitor's node arrives pre-narrowed, so no guard pile ✗ none — you hand-roll predicate guards over the raw 372-member node union yourself
RuleTester
what a human tests		 code strings in, real parser + real traversal, valid/invalid asserted ✗ none — tests hand-build AST trees

What ignorer testing looks like today, in every package in the family:

// packages/ignorers/in-source-vitest-block/tests — hand-assembled AST, not code
{
  name: 'A vitest flag on the left side of a comparison matches',
  path: { node: identifier('x'),
          ancestors: [guardOf(binaryOf(importMetaMember('vitest'), identifier('undefined')))] },
  reason: IN_SOURCE_TEST_IGNORED,
}

That fixture style has three real costs. It mirrors oxc node shapes by hand — every field the parser would set, you set, or the test lies. It bypasses the parse→walk seam entirely, so the pipeline that actually feeds ignorers is never exercised by their own tests. And it reads as structure, not as code — nobody can look at guardOf(binaryOf(...)) and see if (import.meta.vitest !== undefined). The RuleTester shape you keep asking for is the direct fix for all three: a case is a source snippet plus the expected ignored spans, run through the same parseSync the instrumenter uses and the same ancestor-tracking walk.

The honest answer to “why can’t we.” Nothing architectural blocks it. The engine validates only { name, shouldIgnore } — anything that compiles to that shape loads. A defineIgnorer that turns a typed visitor map into the same Ignorer object, and an IgnorerTester that parses snippets and asserts ignored spans, are purely additive: wire contract untouched, engine untouched, instrumenter untouched. The reason it doesn’t exist isn’t a constraint — it’s that each prior round scoped a different layer: the walker duplication got the contract refactor, the guard pile got a closed-shape retype, and the authoring/testing layer fell outside every solved scope each time. Your complaint has been aimed at layer 3 the whole time.
