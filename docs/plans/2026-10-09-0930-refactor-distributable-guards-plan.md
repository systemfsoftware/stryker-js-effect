# Retire the Repository-Local Guards - Plan

## Goal Capsule

No `scripts/guards/*` remains. Each invariant a guard held is either enforced by something distributable (the `repo-checks` flake package of systemfsoftware), by the type system, by a real test of the product, or by the engine itself, or it is dropped with a one-line reason. No enforcer decides by a name, word or regex heuristic. Each kept enforcer is seen failing CI on one honest violation.

## Product Contract

### Requirements

- R1. `scripts/guards/`, `scripts/lib/`, the `guard:projects` and `test:scripts` scripts, and every live reference to them (`package.json`, `.husky/pre-push`, `.github/workflows/nix.yml`, `AGENTS.md`, `test/e2e/AGENTS.md`, `.changeset/README.md`) are gone. Historical plans under `docs/plans/` are records and stay as written.
- R2. A kept invariant names its enforcer and the CI job that runs it. A dropped invariant names its reason in one line.
- R3. No enforcer decides by a regex or name match over source text. It reads a declared property (parsed JSON, the git diff, published documents) or observes the real effect.
- R4. Each kept enforcer fails CI on one honest violation: a planted violation inside a CI step for a CLI check, and for every test-held invariant one pushed violation commit whose CI run is red on that test, reverted by the next commit.

### Findings that contradict the brief

- F1. `check-span-names` never enforced its invariant ("the taxonomy declares every span the CLI emits"). The lifecycle trace of `main`'s e2e run (artifact `e2e-telemetry-…-lifecycle`, 2026-10-09) holds 186 distinct span names under `stryker.cli.run`; 39 of them are absent from `contract/span-taxonomy.json` (for example `RpcServer.digest`, `stryker.prepare.read`, `stryker.instrument.files`). The regex looked only for string literals at eight callee names; the undeclared names come from library-derived spans and a new RPC method. Making the invariant true is a product change to the published taxonomy, outside this unit.
- F2. `scripts/check-changeset.ts`, which `AGENTS.md` START-5 and BREAK-1 cite as a gate, no longer exists; the Changeset Check workflow (pnpm-release-management's reusable `changeset-check.yml`) already runs on every pull request.
- F3. The engine already refuses verdict reuse when the project lockfile changes (`runInputsDigestOf` hashes it), so for any lockfile install an engine upgrade already invalidates the cache. The hand-bumped `VERDICT_SEMANTICS_VERSION` matters only where the engine is not recorded in the project lockfile.

### Scope boundaries

- Not adopting the other `repo-checks` (`subtrees`, `release-age`, `project-membership`): no guard here held them. `release-age` would fail today on the `effect` and `@effect/*` exclusions.
- Not declaring the 39 undeclared spans (F1).
- `scripts/mutation-backstop.ts` is a tool, not a guard, and stays with `scripts/deno.json`.

### Assumptions challenged (edge-first)

- The released tarball lags a release until the `stryker-published` input moves. The law therefore compares against the declared next version (package `version` plus pending intents), not the pending intents alone, so a break already released and versioned does not fail while the base still predates it.
- A manifest `files` entry is read as a path, not a glob: every publishable package here lists plain paths (`dist`, `contract`, `CHANGELOG.md`). Hashing the whole package directory instead would pick up `.turbo/` logs and reports written during a run and invalidate a workspace-linked engine's cache mid-run.
- On a pull request, CI checks out the merge commit, so `merge-base(origin/main, HEAD)` is main's tip and the diff is the pull request's own; on a push to `main` the base equals `HEAD` and no plan is counted.

## Implementation Units

### U1. `repo-checks` from the flake

- **Files:** `flake.nix`, `flake.lock`, `package.json`, `.husky/pre-push`, `.github/workflows/ci.yml`.
- **Approach:** bump the `systemfsoftware` input to the commit that ships `repo-checks` and expose `repo-checks = systemfsoftware.packages.${system}.repo-checks`. Add `gate:repo` (`nix run --no-write-lock-file .#repo-checks -- single-plan --plans docs/plans --base origin/main`) to `gate:tasks`. The pre-push hook runs the same output with `--base "$main_sha" --head <pushed sha>`. CI `check` fetches main's commit graph (`git fetch --no-tags --filter=tree:0 --unshallow origin +refs/heads/main:refs/remotes/origin/main`) before the gate, and one step commits two planted plans and requires exit 1.
- **Verify:** `nix run .#repo-checks -- single-plan …` exits 0 on this branch and 1 on two planted plans; `pnpm lint:conventions` still passes with the bumped gritlint.

### U2. Contract version law as a product test

- **Files:** `packages/stryker-js-cli-contract/package.json`, its `tests/` (the law test, plus test-tree helpers porting the classifier from `scripts/lib/contract-compat.ts` and the pending-intent reader from `scripts/lib/changeset-intents.ts`), `pnpm-workspace.yaml` (catalog `yaml`), `pnpm-lock.yaml`.
- **Approach:** the released documents come from devDependencies on `file:../../.sfs-deps/stryker-js-cli-contract.tgz` and `…/stryker-js-plugin-interface.tgz` under aliases, so pnpm checks them against the lockfile integrity. The committed documents are read from the workspace packages. A document's law is chosen by a property the document declares, never by its file name; an unclassifiable document is a named failure. For each document: incompatibilities = `classifyDocument(released, committed)`. If any, the declared next version (the package's `version` raised by the highest pending intent for it) must clear the required level over the released version (major, or minor while the released major is 0). For `stream.schema.json` the committed `schemaVersion` major must exceed the released one. A package whose committed version differs from the released tarball's while an intent for it is pending is refused as a stale baseline (move `stryker-published` to the latest release tag); the release PR itself has no pending intent and compares normally.
- **Verify:** the test passes on this branch; in a scratch copy, a member removed from a released document with a `patch` intent fails it.

### U3. Engine-keyed verdict reuse

- **Files:** `packages/stryker-js/src/verdict-semantics.ts`, `IncrementalReport.schema.ts`, `IncrementalDiff.schema.ts`, `admit-incremental-report.workflow.ts`, `incremental-diff.workflow.ts`, `mutation-reporting.service.ts`, `read-project.cell.ts`, `run/incremental-reuse.cell.ts`, their tests, `docs/solutions/tooling-decisions/verdict-cache-content-keyed-reuse.md`, a changeset.
- **Approach:** delete `VERDICT_SEMANTICS_SURFACE` and `VERDICT_SEMANTICS_VERSION`. Add `engineDigestOf`: for `@systemfsoftware/stryker-js` and `@systemfsoftware/stryker-js-vm-runner`, resolve `<specifier>/package.json`, and hash the manifest plus every file under the paths its `files` field declares, in sorted relative-path order. Replace `verdictSemanticsVersion: Int` with `engineDigest: String` in the written report, the admission command, the diff command and the per-record key; a mismatch keeps the published `semanticsChanged` reason, so the stream contract does not change. Bump `INCREMENTAL_CACHE_VERSION`, since the report layout changes.
- **Verify:** property tests refuse with `semanticsChanged` on a digest mismatch; in-source laws over the production `packageDigestOf` prove the digest moves with one shipped byte, ignores unshipped files, and refuses an unbuilt `dist` (the lint forbids a `tests/` import of an internal module, so the laws live beside it).

### U4. Delete the guards and their wiring

- **Files:** `scripts/guards/`, `scripts/lib/`, `scripts/deno.json` and `scripts/deno.lock` (drop imports only the guards used), `package.json`, `.github/workflows/nix.yml` (the `tarball-contents` job), `AGENTS.md` (REPO-D2, BREAK-1 and START-5 gates: single-plan names `pnpm gate:repo`, the changeset citations name CI `Changeset Check`), `test/e2e/AGENTS.md` (E2E-1 gate), `.changeset/README.md`, `docs/solutions/tooling-decisions/pnpm-owns-the-changeset-ledger.md` (`test:scripts`).
- **Verify:** `git grep` for each deleted name, excluding `docs/plans/` and `repos/`, returns nothing.

## Verification

- `pnpm format:check`, `pnpm typecheck`, `pnpm lint`, `pnpm test` for the touched packages, `pnpm lint:conventions`, `nix flake check --no-build`.
- No local mutation run and no local `pnpm check:ci`.
- CI on the pull request head: `check` green with the plant step's output. One pushed violation commit carries one honest violation per test-held invariant (a contract member removed under a `patch` intent, a registry journey pointing at a missing file, a digest that ignores shipped bytes) and its CI `check` run is red on each of the three tests; the next commit reverts it and is green.
- The pre-push hook now needs nix and a reachable flake store to push; CI `check` holds the same gate without it.
