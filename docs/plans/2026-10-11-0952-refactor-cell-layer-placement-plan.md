# Cell Layer Placement - Plan

## Goal Capsule

- **Objective:** every Layer and Layer-producing export in the modules R1-R7 govern sits where the cell-architecture service and layer rule puts it. Those modules are the `*.service.ts` modules, the `src/drivers/` folders, and the implementation modules the Layer Inventory names, in `packages/**`, `test/e2e` and the `test/e2e-core` call sites U7 touches. Sites outside that set stay as named gaps (F6-F8).
- **Means:** two stacked pull requests (KTD1). PR A makes the tree pass the gate as written and turns the gate on: the six refused files are fixed, `gritlint.json` enrols `cell-architecture`, the gritlint flake input is re-locked to gritlint main, and `.compound-engineering/config.yaml` pins the packs to a systemfsoftware commit instead of `tree/main`. PR B finishes the placement the gate cannot see: handle-backed implementations, `layerConfig` names, the RPC handler layers in `*Worker.service.ts`, the `src/drivers/` folders, the instrumenter parser module and the e2e harness.
- **Product authority:** the stream supervisor. The rule is settled: `compound-packs/cell-architecture/service-and-layer-boundaries.md` as merged in systemfsoftware#708 (`f2bfe45df4`), the gate turned on in systemfsoftware#728, R1-R14 of systemfsoftware `docs/plans/2026-10-10-1748-refactor-cell-service-layer-structure-plan.md`, and this repository's `docs/adr/0003-driver-implementations-sit-beside-their-service.md`.
- **Authority order:** `CONSTITUTION.md` > `AGENTS.md` > this plan.
- **Stop conditions:** stop and report if the gate refuses a placement this plan calls compliant, if the G1-G3 re-run on the locked gritlint build differs from G3, if gritlint exits 2 or reports an unparseable module after the re-lock, if a move changes a test's verdict, or if Changeset Check asks for a bump this plan does not list.

## Product Contract

### Summary

Six `*.service.ts` modules fail the rule as the gate reads it: they export `*Live` aliases, export module-level Layers, or have class fields named `*Layer`. Eleven more Layers fail it on what their code does, which the gate cannot see. They read `Config` under the name `layer`, are a variant named `stage`, build their implementation on a driver-backed handle or blueprint, import a sandbox driver from a service module, are built by a vendor `.layer(...)` call, or are RPC handler layers built by `toLayer` in a `*.service.ts` that has no Service class. Three driver modules still live under `src/drivers/`. This work moves each one to the place the rule prescribes, removes the aliases, and then turns the gate on so the placement stays.

### Problem Frame

ADR-0003 (accepted 2026-10-10) settled the placement, but only review enforced it. The gritlint rule that systemfsoftware#728 turned on (`cell-architecture/service-exports-no-layer`) is not enrolled in this repository's `gritlint.json`. The locked gritlint, `1d60be3` (`flake.lock`, `nodes.gritlint.locked.rev`), predates `fe886c5`, the merge of gritlint#10, which the rule needs to parse `dual` overload type literals. `.compound-engineering/config.yaml:2-4` names three packs by `tree/main` URL, so pack text can change under the repository without any commit here.

### Requirements

Placement:

- R1. No `*.service.ts` exports a module-level Layer, a `*Live` binding or a Layer alias, and no class field in one is named `*Layer`, `*Live` or `Default`. Source: sfs plan R4, R12 and R14.
- R2. No `*.service.ts` holds an import of a driver, runtime or type-only, static or through `import()`: the contract never imports or references the driver (pack `service-and-layer-boundaries.md`, section 3, invariant 2). Driver means an import of one of these specifier families, and only these: `node:*`, `@effect/platform-<runtime>`, `vitest`, `oxc-parser`, `typescript`, `@opentelemetry/*`, `@systemfsoftware/effect-microsandbox` and `@systemfsoftware/vitest-config/telemetry`. The one named exception is F8 (`guest-job.service.ts`'s `MicroVM` types). Source: sfs plan R2.
- R3. An implementation that needs only Effect and abstract tags is a `static readonly layer` (or `layerConfig`, `layerTest`, `layerNoop`, `layer<Variant>`) on its Service class. Source: sfs plan R3 and R4, ADR-0003:38.
- R4. An implementation that imports a driver, or builds on a handle or blueprint that does, lives in a flat module beside its service. That module exports module-level `make` and `layer`, and composition roots and tests are its only importers. Two exceptions: an adapter module that provides a service tag it does not own keeps its `layer<Variant>` export names (rows 1-2), and a concrete runtime binding whose only consumer is the composition root is built in the root (row 30). Source: sfs plan R5 and R6, ADR-0003:35-37.
- R5. A Layer member that reads its options through `Config` is named `layerConfig`. Source: sfs plan R4, pack `service-and-layer-boundaries.md` (tier 2 names).
- R6. No `src/drivers/` folder remains in any package. Source: sfs plan R6, ADR-0003:37.
- R7. Each move preserves behaviour. Existing tests prove it, and no test is bent to fit.

Gate and packs:

- R8. `gritlint.json` enrols `cell-architecture`, and the gritlint flake input is locked to gritlint main as it stands at PR A time (at or after `fe886c5`; main was `d96dc51c1`, gritlint#14, on 2026-10-11). One input changes, through a normal lock update. G1-G3 are re-run on that exact build.
- R9. `pnpm lint:conventions` exits 0 with zero findings and no unparseable module. A planted `*.service.ts` violation exits 1 with rule id `cell-architecture/service-exports-no-layer` and exits 0 once removed. Local gate runs use the flake-built binary (`nix build .#gritlint --print-out-paths` or `nix run .#gritlint -- check`), never `./bin/gritlint`, which execs the first `gritlint` on PATH (`bin/gritlint:13-17`); PATH here holds an older build. - R12. Each PR body carries a table with the columns Layer, tier, file, and why (pure, or which driver), and a "How an agent consumes this" section covering every new or changed surface: gate finding, CLI output and report field.
- R13. Every removed or renamed public export is listed with its `etc/*.api.md` entry, or with the fact that it has none, and gets a changeset at the matching bump.

## Planning Contract

### Key Technical Decisions

- KTD1. **Two PRs, stacked (OP13b), gate first.** PR A (U1-U5) fixes the six files the gate refuses (G1-G3), renames `RunEnvironment.stage` to `layerStage` so stryker-js ships one major, and turns the gate on with the lock and pack pin. PR B (U6-U10) moves everything the gate cannot see. Its base is PR A, and it touches `vitest-runner/src/main.ts` and `vitest-test-runner.ts` after PR A. There are three reasons for this order. The gate starts guarding the tree before the larger PR B moves land. The supervisor's rulings on Q1 and Q2 change only PR B. And G3 proves the PR A fixes are sufficient for the gate. A single PR would also pass CI. It is not chosen, because a gritlint lock regression would then revert with code moves.
- KTD2. **Classification reads the code, not only the gate's flags.** The gate refuses six files (G1, G2). Eleven more Layers violate R1-R5 in ways the gate cannot see: two `*.service.ts` modules import a driver the preset does not list, a module-level Layer built by a vendor `.layer(...)` call passes sfs R12, two RPC handler layers built by `RpcGroup.toLayer` pass sfs R12, sfs R13 leaves reach through a handle to the package graph, and the gate does not check member names other than `*Layer`/`*Live`. Each of these is moved or renamed here, and each gate miss is recorded as a follow-up.
- KTD3. **Handle-backed and blueprint-backed implementations are driver-backed (R4).** The pack's tier 2 is "Pure Effect: imports no driver or platform runtime", and section 3 invariant 1 forbids a dependency on a platform runtime even indirectly through the contract module. `CheckerRuntime.service.ts:22-23` imports `ts-compiler.blueprint.ts` and `ts-compiler.handle.ts` at runtime, and the handle imports `typescript` at runtime (`ts-compiler.handle.ts:25-26`). `VitestSession.service.ts:17` imports `VitestRuntime.blueprint.ts`, which imports `vitest/node` at runtime. `fixture-cache.service.ts` and `stryker-cli-runner.service.ts` import `warm-sandbox.handle.ts`, which imports `MicroVM`. None of these needs only Effect and abstract tags (R3), so each implementation moves to a sibling module (Q1, ruled: move). Each service module keeps its class and its Shape and holds no driver import, type-only included (R2). `CheckerRuntime.service.ts` drops its `import type { Diagnostic } from 'typescript/unstable/async'` (`:17`), because only `createErrorText` (`:61`), which moves, uses it.
- KTD4. **Tier-3 module names.** Each new sibling exports `make` and `layer`. Filenames follow the repository's precedent `<technology>-<capability>.ts` (`oxc-source-parser.ts`, ADR-0003:41): `typescript-checker-runtime.ts`, `vitest-session.ts`, `vitest-test-runner.ts`, `microsandbox-guest-job.ts`, `microsandbox-fixture-cache.ts`, `microsandbox-stryker-cli-runner.ts`. A sibling named without its technology would share its service file's basename, so the path would not show which file is the implementation (ADR-0003, Consequences, "Bad"). A module that only sheds a wrong suffix or a `drivers/` folder keeps its basename: `trace-context-rpc.ts`, `Parser.ts`, `CheckerWorker.ts`, `TestRunnerWorker.ts`, `vitest-node.ts`, `vitest-pool.ts`, `oxc-program.ts`. `trace-context-rpc.ts` keeps its public export names `layerTraceContextClient`/`layerTraceContextServer`, which are `layer<Variant>` names (R4), not `*Live`/`Default`.
- KTD5. **Composition roots bind adapter to adapter.** `vitest-test-runner.ts`'s `layer` requires `VitestSession` and stops providing it. The root `packages/stryker-js-vitest-runner/src/main.ts` provides `vitest-session.ts`'s `layer`. The same holds in `test/e2e/src/Harness/harness-layers.ts`, the harness root (imported only by `test/e2e/tests/__fixtures__/e2e-harness.fixture.ts:18` and `global-setup.ts:6`). Its tier-1 `HarnessServicesLive`/`HarnessPlatformLive` stay: a composition root may hold tier 1 (pack tier table, row 1).
- KTD6. **Bumps (BREAK-1).** `@systemfsoftware/stryker-js` major (19.0.0), `@systemfsoftware/stryker-js-plugin-runtime` major (7.0.4), `@systemfsoftware/stryker-js-typescript-checker` major (8.3.2). `@systemfsoftware/stryker-js-vitest-runner` and `@systemfsoftware/stryker-js-instrumenter` get `none`, because every change is internal to `src/` and neither package's exports map or api report changes. `test/e2e` (`@systemfsoftware/stryker-e2e`, private) gets an intent only if Changeset Check asks for one.
- KTD7. **No new permanent test.** Each unit is a move or rename. Its proof is `tsc -b` (every call site resolves), the existing tests named per unit, `api:check`, and the gate. The `test-layer-selection` admission gate admits nothing new. Moved service and adapter modules keep their existing integration coverage, and composition roots are exempt (smoke boot only). The planted probe is a throwaway gate check, not a test. Mutation globs select only `*.workflow.ts` and `*.schema.ts`, so no mutant id moves. The one type that moves into a `*.schema.ts` (`RunFilter`, U3) is a type, so it adds no mutant.
