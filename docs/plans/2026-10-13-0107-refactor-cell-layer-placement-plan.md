# Cell Layer Placement - Plan

- **Objective:** every Layer and Layer-producing export in the modules R1-R7 govern sits where the cell-architecture service and layer rule puts it. Those modules are the `*.service.ts` modules, the `src/drivers/` folders, and the implementation modules the Layer Inventory names, in `packages/**`, `test/e2e` and the `test/e2e-core` call sites U7 touches. Six kinds of remaining debt stay as named gaps: runtime bindings outside those modules (F6), edges into driver modules from pure code (F7), the type-level driver references kept in three Shapes (F8), the e2e fixture install (F9), `*.service.ts` modules that hold no Service class (F10), and the provisional `TypeQueryLive` entry (F11).
- **Means:** two stacked pull requests (KTD1). PR A fixes the six files the gate refuses and proves it with the pinned gate run from outside the repository (KTD8, H9). PR A does not enrol the gate: `gritlint.json`, the gritlint lock and the `.compound-engineering/config.yaml` pack list are judgment surfaces that grade this work, so they stay byte-identical to `main`, and PR A's body carries the enrollment request for Stream K (CONST-E7, H9). PR B finishes the placement the gate cannot see: handle-backed implementations, `layerConfig` names, the RPC handler layers in `*Worker.service.ts`, the `src/drivers/` folders, the instrumenter parser module and the e2e harness.
- **Product authority:** the root's outcome: stryker-js-effect follows the cell-architecture rule settled in systemfsoftware#708 and #728. The rule's text is `compound-packs/cell-architecture/service-and-layer-boundaries.md` at systemfsoftware `02bf9653b1` (which contains `f2bfe45df4`, #708, and `ee27f80c2d`, #728), R1-R14 of systemfsoftware `docs/plans/2026-10-10-1748-refactor-cell-service-layer-structure-plan.md`, and this repository's `docs/adr/0003-driver-implementations-sit-beside-their-service.md`. Every design choice below is this plan's own and names its source (Decisions H1-H9). Pack line citations (`:N`) refer to that file at `02bf9653b1`.
- **Authority order:** `CONSTITUTION.md` > `AGENTS.md` > this plan. CONST-E7 (H9) binds over every earlier gate unit of this plan.
- **Product Contract preservation:** changed: R8, R9, R10 and AE3 - the root's CONST-E7 ruling of 2026-10-13 moves the enrolment, the lock and the pack pin to their owner (H9); R8 and R10 are no longer delivered here, and R9 and AE3 become the out-of-repository proof.

## Product Contract

### Summary

Six `*.service.ts` modules fail the rule as the gate reads it: they export `*Live` aliases, export module-level Layers, or have class fields named `*Layer`. Eleven more Layers fail it on what their code does, which the gate cannot see. They read `Config` under the name `layer`, are a variant named `stage`, build their implementation on a driver-backed handle or blueprint, import a sandbox driver from a service module, are built by a vendor `.layer(...)` call, or are RPC handler layers built by `toLayer` in a `*.service.ts` that has no Service class. Three driver modules still live under `src/drivers/`. This work moves every refused Layer and ten of the eleven to the place the rule prescribes and removes the aliases. It does not turn the gate on: PR A's body asks Stream K to enrol it (H9). Once enrolled, the gate refuses, in any `*.service.ts`, a `node:*`, `@effect/platform-*`, `@effect/sql-*` or `@effect/ai-*` import, a module-level Layer built by a `Layer.*` call, a `*Live` export, a Layer alias, and a class field named `*Layer` or `*Live`. It does not see the other driver families, `toLayer` and vendor `.layer(...)` Layers, other member names, or reach through a handle (F1-F5), so review still guards those. The eleventh Layer, `BakedFixtureCache.layer`, is the e2e fixture install, which another stream owns; it stays as named gap F9 (H1).

### Requirements

Placement:

- R1. No `*.service.ts` exports a module-level Layer, a `*Live` binding or a Layer alias, and no class field in one is named `*Layer`, `*Live` or `Default`. Source: sfs plan R4, R12 and R14.
- R2. No `*.service.ts` holds an import of a driver, runtime or type-only, static or through `import()`: "the core contract never imports or references the driver" (pack `:103`), and a service module imports only "pure types, Effect primitives ... and platform service tags" (pack `:24`). Driver means an import of one of these specifier families: `node:*`, `@effect/platform-<runtime>`, `vitest`, `oxc-parser`, `typescript`, `@systemfsoftware/effect-microsandbox`, `@systemfsoftware/vitest-config/telemetry`, and the OpenTelemetry SDK and exporter packages. `@opentelemetry/api` is not a driver (H2), but pack `:24` keeps it out of `*.service.ts` too. The one named exception is F8 (`guest-job.service.ts`'s `MicroVM` types). Source: sfs plan R2, H2.
- R3. An implementation that needs only Effect and abstract tags is a `static readonly layer` (or `layerConfig`, `layerTest`, `layerNoop`, `layer<Variant>`) on its Service class. A pure implementation of a tag that another package owns cannot sit on that class, so it sits in a flat module that is not a `*.service.ts` and keeps `layer<Variant>` export names (rows 1-2). Source: sfs plan R3 and R4, ADR-0003:38.
- R4. An implementation that imports a driver, or builds on a handle or blueprint that does, lives in a flat module beside its service. That module exports module-level `make` and `layer`, and composition roots and tests are its only importers (pack `:29`, `:39`). Two exceptions. A concrete runtime binding whose only consumer is the composition root is built in the root (row 30). A plugin package that is itself the driver package for a host contract may also publish its adapter on a subpath barrel, as pack `:98` and `:104` describe for a separate driver package: typescript-checker's `./runtime` already publishes the driver-backed `nodes` (`src/runtime/mod.ts`) and gains `TypeScriptCheckerRuntime` (U7). Source: sfs plan R5 and R6, ADR-0003:35-37.
- R5. A Layer member that reads its options through `Config` is named `layerConfig`. Source: sfs plan R4, pack `service-and-layer-boundaries.md` (tier 2 names).
- R6. No `src/drivers/` folder remains in any package. Source: sfs plan R6, ADR-0003:37.
- R7. Each move preserves behaviour. Existing tests prove it, and no test is bent to fit.
