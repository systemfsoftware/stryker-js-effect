# Dissolve test/e2e-core - Plan

## Goal Capsule

No package, directory or commit scope is named `e2e-core`, and no other core/common/shared/utils package holds test tooling. E2e harness code lives in `test/e2e`, bench code in `test/bench`, and code that decodes a published product output lives in the product's contract package, tested there as product code. Four small PRs, one stack on `main`.

Review status: ce-doc-review is skipped for this gate because the root reviews the plan this cycle (r42).

## Product Contract

### Requirements

- R1. No package, directory or workspace entry named `e2e-core`, and no replacement core/common/shared/utils package for test tooling. New commits stop using the `e2e-core` scope; past commit messages are history and stay.
- R2. E2e harness code lives in `test/e2e`; bench code lives in `test/bench`.
- R3. Code that decodes a published product output lives in its contract package, with property tests that can fail on a plausible bug and no mockery.
- R4. Every e2e journey and every bench comparison keeps its current verdict. The one exception is the bench comparison whose subject is this package (D2).
- R5. #306's fixture-manifest key refusal and #311's committed-lock bake still hold.
- R6. Product tests (`packages/*/tests`) import no test-harness package and name no test-harness project.
- R7. Mutation grades the shipped product only: test tooling leaves `mutation.yml` and `kill-matrix.yml`.
- R8. A harness test survives only if a person running the e2e lane or the bench relies on what it checks. The inventory gives a keep / move / delete reason for each file.
- R9. Other streams' open PRs land after the cut by merging `main`. This stream edits none of them.

### Scope Boundaries

- Not here: fixing the flaky `∀x_ManifestDocument_=x` law. It moves unchanged and keeps running (see Premises P12 for who owns the fix).
- Not here: enrolling `stryker-js-cli-contract` in Mutation. That is Stream K's file; see P4.
- Not here: editing Stream B's reuse suites, beyond the one data line D4 names.
- `docs/plans/**`, `docs/brainstorms/**` and the committed lockfile snapshots under `packages/stryker-js/tests/__fixtures__/lockfile-closure/real/` keep the name. They are dated records or frozen test inputs. Live docs change: `test/e2e/AGENTS.md`, `test/e2e/README.md`, `test/e2e/oxlint.config.ts` and `docs/solutions/build-errors/e2e-bake-resolved-an-npm-alias-edge-from-the-registry.md`.

## Decisions (each needs the root's ruling at plan review)

- D1. **Bench imports the shared install modules from the e2e harness.** `catalog-resolution.ts` and `install-closure.{schema,workflow}.ts` are the only modules both lanes import (P6). They move to `test/e2e/src/Harness/`, and `@systemfsoftware/stryker-e2e` gains a source-only `exports` map for them, which `test/bench` imports. Rejected: a third package (the grab-bag again); a copy in each lane (two sources of I1/I2); bench owning them (the bake is the e2e harness's job, and the bench only reuses the install plan, `ClosureInstall.specs`).
- D2. **The bench corpus entry `test/e2e-core` is re-pointed to `test/bench`.** The new entry mutates `src/summarize-bench.workflow.ts` and runs its property test. It has the same workload shape as today's entry (one workflow under its laws) (`test/bench/corpus.json:14`). The first bench run after D reports that comparison as `workload changed`, not a verdict, because its subject changes. Rejected: re-pointing to `test/e2e`. Its vitest config would put container journeys in the bench's path.
- D3. **E2E-1 is reworded, not dropped.** Today `test/e2e` MUST NOT declare `test` (`test/e2e/AGENTS.md:19`). After the cut, `test` runs only the in-process suites (`src/__tests__`, `in-process/`) under their own vitest config, and container journeys stay under `test:e2e` alone. The rule's purpose holds: no container journey in `pnpm test`, `check:ci` or the macOS matrix. Its gate stays the status-closure suite, which then runs under `test/e2e`'s `test`. Whether a repo-checks guard also refuses a `test` script in `test/e2e` is [unverified]; PR D checks it first and, if one exists, asks the root before touching it (GATE1). Rejected: deleting the harness laws for lack of a runner, which breaks R8's keep list.
- D4. **The product test's mirror of Mutation's projects drops `test/e2e-core` in PR A.** `MUTATED_PROJECTS` in `packages/stryker-js/tests/lockfile-closure-digest.integration.test.ts:29-34` lists the projects `mutation.yml:36` mutates and checks each against the live lockfile (`:516-520`). The line changes in the same commit as `mutation.yml:36`, or the live scenario falls back once the importer is gone. Stream A's #321 also edits this file, and if it is one of Stream B's suites [unverified], the one-line change is announced to B before PR A opens. Neither stream's branch is edited.
- D5. **The run-event stream decoder becomes a contract codec, not a workflow.** `RunEventStream` in `stryker-js-cli-contract` decodes a whole stdout text to `ReadonlyArray<RunEvent>`: blank lines skipped, the first undecodable line refused with its 1-based number. It encodes as one `RunEventWireLine` per event. A codec keeps the published package off `@systemfsoftware/effect-cell-types`; KTD1 of `docs/plans/2026-09-27-0424-refactor-contract-first-mutation-oracles-plan.md` keeps the contract on `plugin-interface` and `effect` only [unverified against today's `package.json`]. Rejected: moving `decodeStream` as a `Workflow.make` (adds that dependency to a published contract).
