# packages/frameworks

Format plugins that hand the core the script regions of a framework file, plus the types-only interface both sides depend on.

## Boundaries

- `@systemfsoftware/stryker-framework-interface` is types only and Effect-free: no source or built file exports a value or a class, and no dependency block names `effect` or `@effect/*`. Gate: `pnpm --filter @systemfsoftware/stryker-framework-interface build`, plus the preset's `no-restricted-imports` ban under `pnpm lint`.
- The interface tier re-exports the AST vocabulary from `@systemfsoftware/stryker-ignorer-interface` (`export type *`), never re-derives it, and keeps that package in `dependencies` so the emitted declaration holds one physical copy of the recursive node type. Gate: `pnpm --filter @systemfsoftware/stryker-framework-interface build`.
- A framework plugin package follows the ignorer package template: `src/mod.ts` entry, `tsdown` build, an api-extractor report under `etc/`, the shared oxlint preset, `@systemfsoftware/source` as the dev condition. Gate: `pnpm --filter @systemfsoftware/stryker-js-svelte build` and `pnpm --filter @systemfsoftware/stryker-js-svelte api:check`.
- No framework package imports `effect` or any `@systemfsoftware/stryker-js-*` package in any dependency block: the contract is plain objects and synchronous functions, so a plugin cannot re-couple to the host's Effect version. Gate: `review` — the reviewer reads every dependency block; `wrong:` `effect` or a `@systemfsoftware/stryker-js-*` name under `dependencies` or `devDependencies`, `right:` `@systemfsoftware/stryker-framework-interface` plus this package's own test tooling.
- `plugins` entries are bare package names resolved from the project (`'@systemfsoftware/stryker-js-angular'`) or explicit `file:` URLs; user configs never call `import.meta.resolve`, and plugins are never auto-discovered. Gate: `pnpm --filter @systemfsoftware/stryker-js test`.
- A framework plugin package declares the extensions it claims in its `package.json` under `"strykerFramework": { "extensions": [...] }`, and the host reads that field from installed packages to name the package in a skip reason without importing the module. Gate: `pnpm --filter @systemfsoftware/stryker-js test`.
- The Svelte plugin supports Svelte 5 only (`svelte` peer `^5.0.0`), parsed on the modern AST; no older Svelte is claimed. Gate: `pnpm --filter @systemfsoftware/stryker-js-svelte test`.
- Hooks are synchronous and total: `parse` and `disableTypeChecks` answer a `FrameworkParseResult` — a parse failure is a value, never a throw — and `transform` and `print` are pure functions of the document. Gate: `pnpm --filter @systemfsoftware/stryker-js-angular test`.
- A peer is resolved at module evaluation (top-level `await import`) and refusal is data: a missing peer, one outside the range `peerDependencies` declares, or one that does not export what the plugin needs exports a `FrameworkRefusal` (`PeerMissing`, `PeerVersionUnsupported`, or `PeerUnrecognized`) instead of the framework, and the host treats every reason as a configuration error (exit code 2); any other failure importing the peer propagates as a crash. Gates: `pnpm --filter @systemfsoftware/stryker-js-svelte test` and `pnpm --filter @systemfsoftware/stryker-js test`.
- A plugin owns exactly the extensions its claim names; when two plugins claim one extension, the earlier module in plugin order wins and the loser is reported as shadowed. Gate: `pnpm --filter @systemfsoftware/stryker-js test`.
- A script region is the text between a `<script>` tag's tags, and only the formats that declare template expressions produce expression regions. Gate: `pnpm --filter @systemfsoftware/stryker-js-angular test` and `pnpm --filter @systemfsoftware/stryker-js-svelte test`.
- The instrumentation header lands in a module script, only once mutants land in the file, and never a second time: a component without mutants prints byte-identical to its input. Gate: `pnpm --filter @systemfsoftware/stryker-js-svelte test`.
- Every ignore reason a plugin emits is the string its framework requires, verbatim. Gate: `pnpm --filter @systemfsoftware/stryker-js-angular test`.
- Each plugin package holds 100% per-file coverage of every file under `src/`. Gate: `pnpm --filter @systemfsoftware/stryker-js-angular test` and `pnpm --filter @systemfsoftware/stryker-js-svelte test` — both `vitest.config.ts` files set `coverage.thresholds` to `{ 100: true, perFile: true }`.
- Each package's published surface is exactly its `etc/*.api.md` report; regenerate it with `api:update`, never hand-edit it. Gate: `pnpm --filter <package> api:check`.
